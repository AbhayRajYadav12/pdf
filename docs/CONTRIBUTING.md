# Contributing

Install pnpm 10.18.3 and Node 22. Run `pnpm install`, then `pnpm typecheck`, `pnpm lint`, and `pnpm test:unit` before opening a pull request.

TypeScript is strict. Packages export source through the `development` condition and compiled JavaScript otherwise. Tests and `tsx` use the development condition. Production images run `tsc` first.

Keep secrets out of git. `.env` is ignored. Do not log document text, session cookies, or API keys.

Product changes that affect retrieval, citations, or authorization need a unit test. The end-to-end test in `tests/e2e/workflow.test.ts` covers register, upload, a cited answer, abstention, deletion, and a second workspace. It uses in-memory MongoDB, the memory vector store, deterministic embeddings, and the fixture generator. Do not point that test at production settings.

Do not add measured accuracy numbers to the docs unless the command that produced them is in the same change and the report file is generated by `pnpm eval` or a clearly labeled external run. Fixture metrics are not Gemini metrics.

The UI lives in `apps/web`. After a visible change, check the landing page, registration, the empty dashboard, upload, and chat states in a browser.
